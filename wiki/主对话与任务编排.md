## 🧩 Agent Graph（"先做 A、再 B 和 C 并行、最后汇总"的顺序调度工作台）

### 先选一个适合的场景

在顶栏「场景切换」按钮里，先挑你现在的工作心情：

| 心情 | 点哪个 | 能看到什么 |
|---|---|---|
| 只是想先聊 / 随便试 | **陪伴** | 小星立绘 + 礼物 / 星标工具栏 |
| 真的要做任务、跑命令 | **工作台** | 网格科技风 + 创建任务图/审查/终端快捷入口 |
| 不想被打扰，专心干完 | **专注** | 暗调聚焦 + 极简输入区 |

> ⚠️ 无论切到哪个场景，**对话 / Graph / Review 三模式按钮都还在**，你可以一边聊一边切场景。

Agent Graph 适合需要**多步骤、依赖关系或不同角色协作**的目标。

### 创建流程

1. 切换到 **Agent Graph**。
2. 点击 **创建任务图**。
3. 输入任务图名称。
4. 为每个节点设置**名称**、**执行角色**和**指令**。
5. 为后续节点选择**前置依赖**。
6. 保存后执行任务图。

### 可用角色

- 代码工程
- 界面设计
- 安全审查
- 发布交付

> 角色用于明确执行**重点**，不代表可以绕过权限。

## 🗂 Mission Dock

右侧 **Mission Dock** 是任务事实中心：

| 页签 | 你会看到什么 |
|---|---|
| 概览 | 任务数量、运行状态和待审批项 |
| 文件 | 当前任务相关文件 |
| 变更 | 工作区 Git 变更 |
| 审批 | 处理需要确认的操作 |
| 终端 | 在当前工作区执行命令 |
| 证据 | 查看运行过程和结果记录 |
| 审查 | 汇总交付信息 |

---

## ✅ Review / Deliver

任务接近完成时切换到 **Review / Deliver**：

1. 生成**交付审查**。
2. 核对**修改范围**和 **Git 变更**。
3. 查看**测试**和**运行证据**。
4. 阅读**风险清单**。
5. 必要时发起**深度审查**。
6. 确认**交付摘要**与实际结果一致。

> ❗ **核心原则**：不要只依据「任务完成」状态判断交付。测试、变更和证据必须互相吻合。

---

## ⏸ 中断与恢复

| 情况 | 怎么做 | 结果 |
|---|---|---|
| 想立刻停 | 运行中点 **停止** 按钮 | 当前执行中断，不删历史 |
| 临时有事走开 | 直接关窗口 / 暂停任务 | 已有对话和证据都会保留 |
| 第二天想接着干 | 重新打开绑定的任务 | 继续原上下文，不从头说 |
| Provider 掉了 | 先恢复连接 → 再重试 | 未完成的操作自动续上 |
