## ✅ 已经做完的 11 件事（P0 全景）

> 这部分如果你不是特别关心工程细节，跳着看也行。反正就一句话总结：**该有的基础能力全部按预期落地了，单测全绿，关键路径上了不变式。**

| # | 名称 | 实际交付物 | 一句话说它解决了啥 |
|---|---|---|---|
| P0-10 | 📑 文档机制 | `Agent Notes` 七种档案模板 + 七类目录 | 改代码以后自动写笔记，半年以后回看不用靠脑内存。 |
| P0-1 | ⚙️ 能力 Seam 三角色 | Provider / Seam / Facade 三层解耦接口 | 想换工具后端、换审批后端、换沙箱后端，代码一行替换就行，不用全项目找引用改。 |
| P0-2 | 🎛️ 配置三层组合 | Profile / Bundle / Patch 三层合并 + Zod 校验 | 官方配置一套、团队再改一层、你自己再覆盖一层，三层不打架；哪个字段改坏了立刻报错。 |
| P0-3 | 🚦 不变式注册中心 | 10 条 invariant，CLI + runtime 双模式 | 运行时每跑一次模型就自动扫一遍最关键的 4 条；CI 里跑全量 10 条。有任何配置乱了，早发现早修，不等到线上崩。 |
| P0-4 | 💾 会话持久化双后端 | JSONL + SQLite 两实现，崩溃兜底三阶段 closeReason | 突然断电、异常退出，会话数据不丢；崩了以后重新打开能自动捡回没保存的记录。 |
| P0-5 | 🔧 工具执行流水线五段式 | 前执行 / 调用前 / 执行中 / 调用后 / 后执行 五段 | 任何工具调用之前都能插你自己的拦截逻辑（比如打日志、检查权限、改参数），工具结果也能统一后处理。 |
| P0-6 | 🧱 沙箱多后端 | 本地临时目录 / 本地子进程 / 云端沙箱三实现 + 逐调用策略 | 跑代码不用再怕动到真实文件；同一个会话里，简单命令用本地快的，危险命令自动切云端沙箱。 |
| P0-7 | 🤹 子智能体多 Provider | 内注册中心 + 薄壳 Facade + Fail-closed | 开子任务有三种路由挑；没装 Provider 直接报错不沉默失败；兼容旧代码。 |
| P0-8 | 🔙 可继续子智能体 + Activation 快照 | 激活态快照 + fork/resume 真句柄 | 开个小助手跑一半暂停了，关了软件第二天打开还能接着上次的断点继续往下干。 |
| P0-9 | 🛠️ Workflow 引擎（真 worker） | worker_thread 独立进程 + 心跳监控 + 双实现 | 复杂流程调度跑在独立线程里，不会把主对话界面卡死掉；挂了自动杀，重试兜底。 |
| **P0-11** | 🛡️ 审批瀑布 + 权限预设 | 三态状态机 + 四态响应 + 2 条内置 Preset + I3/I10 双 invariant | 写文件、跑危险命令这些敏感动作，终于**先审再放**了；超时无人审自动升级给上级，流程能全记录可审计。 |

> 「踩坑一句」P0-11 做的时候踩了 8 轮小坑：字段拼写错、异步可选语法歧义、旧预设名没全换、测试断言漏更、类型守卫没加全。最后一遍跑 tsc + 单元测试才算真的稳了。这些坑全写进决策档案了，下次做类似的不用再踩一遍。

### 🟡 P1 · 9 件事（三条并行线，P0 关闸后立刻启动）

P1 不是一件接一件串行的。我们拆了三条并行线，开发资源够的话三条可以同时跑，互相不打架。

#### 并行线 A · 类型与 RPC（得按顺序 1→2 做）

| # | 名称 | 大概什么时候可用 | 用户能感受到什么变化 |
|---|---|---|---|
| P1-1 | 🗺️ Typert 类型图 + API Gateway | P1 前半段 | 跨模块传参再也不用手写"接口文档"，类型不一致立刻红，IDE 跳转一步到位；外部 HTTP 调用统一走一个网关入口，鉴权/重试/限流一处配。 |
| P1-2 | 🌐 云端沙箱 + 共享运行世界 | P1 中段 | 代码跑在云端真隔离环境，本地再怎么折腾也不污染；多个任务共享同一个云环境，不用每次启动都重新装依赖。 |

#### 并行线 B · 投影与压缩（独立线，和 A 没关系，和 C 也没关系）

| # | 名称 | 大概什么时候可用 | 用户能感受到什么变化 |
|---|---|---|---|
| P1-3 | 🪞 会话投影单元 | P1 前半段 | 超长会话按视图去切片，看历史不用拉全量几万条；摘要、统计、任务列表都能投影出来，打开老会话秒出。 |
| P1-4 | 📏 压缩多策略 | P1 中段 | 会话太长了压缩，不是一刀切全丢；有"只留工具结果"、"保留关键节点"、"便宜模型摘要"三种策略自动选；压缩前留一份原始副本不毁档。 |
| P1-5 | 🎭 子智能体身份投影 | P1 中段 | 开再多子智能体也能分清谁干了啥；子任务有自己的身份卡片和结果汇总，父线程不用每次打开子线程才看进度。 |

#### 并行线 C · 领域 / 任务 / 服务（四件互相独立，能穿插做）

| # | 名称 | 大概什么时候可用 | 用户能感受到什么变化 |
|---|---|---|---|
| P1-6 | 🧭 三种模式（问答 / 计划 / 目标） | P1 全段任意时 | 三种模式明确定义：**你问我答模式**（不追着你要下一步）、**计划模式**（先调研写计划给你批再动手）、**目标模式**（告诉小星我要啥，她自己拆任务自己追进度）。 |
| P1-7 | 📋 后台作业注册表 | P1 全段任意时 | 跑视频、批量生成、大文件下载这种长任务，统一挂在后台作业面板里，进度条、重试按钮、日志查看全有，不再盯着面板干等。 |
| P1-8 | 💻 LSP 代码智能接口 | P1 后段 | 写代码终于不是瞎写了：跳转定义、找引用、错误高亮、自动补全，和 VSCode 里一模一样；支持 TS/Python/Rust/Go/Java 五门语言。 |
| P1-9 | 🔐 凭据 + 配置双能力 | P1 全段任意时 | 你给的 API Key 再也不是明文放配置文件了；凭据和配置分家：敏感的进凭据保险箱（加密存，只在需要时才解锁），外观设置、偏好、快捷键走普通配置。 |

> 「闲话补一句」P1 一共 9 件，并行线拆成 A/B/C 三条是因为它们几乎没耦合——这是 P0 层 11 件事情先做的回报。如果不先把 Seam 三层、不变式、持久化、流水线、沙箱这些底打好，P1 每一件事都会和另外 8 件打架，只能一件件串行写，那要慢一倍。现在能三条并行，全靠前面花了时间拆架子。

### 🟢 P2 · 5 件事（P1 完成度 ≥ 七成再开，按顺序 1→2→3→4→5）

P2 的主题是「对外」：别人能用、别人能接、别人能写插件。这些事情**必须等地基稳到一定程度**才能开，不然别人刚接进来我们里面接口又改了，别人会骂。

| # | 名称 | 启动门槛 | 大家能感受到什么 |
|---|---|---|---|
| P2-1 | 🔌 ACP 服务端 + 客户端 | P1-7（后台作业）+ P1-9（凭据配置） 完成 | 第三方程序可以接小星：你电脑上其他软件、浏览器插件、手机 App，都能调小星做事；小星也能对外广播事件。 |
| P2-2 | 📤 代码模式子调用传输 | P1-3（会话投影）+ P1-4（压缩） 完成 | 代码脚本模式和外部工具的双向传参有统一协议；复杂对象、流式输出、进度回调都能传。 |
| P2-3 | 🧭 Web 路由注册表 | P1-9（凭据配置）+ P2-1（ACP） 完成 | Web 面板、远程页面终于有正经路由了；插件想加页面也能走路由注册，不用自己硬塞 iframe。 |
| P2-4 | ♨️ HMR 热更新 + 客户端模块 | P2-3 路由注册表完成 | 改了小星的界面和插件不用重启整个软件，热更新就生效；界面开发效率翻倍。 |
| P2-5 | 🏭 目录生成器 + CI 校验 | P1 完成度 ≥ 90% | 目录结构、核心接口、文件命名规则全自动化校验；新贡献者提交 PR 就自动跑一遍，不通过打回，省人工看。 |

## 🎱 关于"什么时候能用"的老实回答

> 这部分不是给老板汇报的 PPT，是给你看的真心话。

**🔴 P0 关闸**（就剩 P0-12）：**几天以内**。缓存命中率 invariant 我们跑过基线，其实目前已经高于 90%，但是得把脚本和 invariant 正式接进 CI，以后每次 PR 自动跑。这项不是大工程，收尾很快。

**🟡 P1 全 9 项可触达的体验**：P1 里面有些功能会先出（比如 P1-3 会话投影一开，用户立刻能感觉到打开老会话不卡了；P1-6 三种模式一定义，对话里的模式切换立刻就合理了）。P1 是"边做边见效"的阶段，不需要等 9 项全部做完才感觉变好。

**🟢 P2 对外开放**：P2 没有 8-9 成稳，我们不会开放。这部分我们不急着吹。先把本地单用户体验做好，比什么都实在。对外开放搞早了，接口一改，大家一起骂娘。

> 「取舍一句」路线图这种东西，写得越宏大越容易成为笑话。我们故意不写"某月某日必定发布"的死线，只写先做什么后做什么、每做完一件用户能感受到什么。时间永远估不准，但前后顺序和依赖关系不会乱。
