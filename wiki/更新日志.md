## ✦ HELIOS V3.12 · 三阶段 9 项高价值扩展 · Provider 适配器 + E2B 沙箱 + LSP + SDK 门面
> **日期**：2026-08-15
> **主打**：差值合并 DeepSeek Harness + kun-reference 二仓库,提炼 P0 2 项 + P1 7 项共 9 个高价值模块一次性落地,**全部内部自研实现 · 遵循「本地优先 · 源码不公开」规则**

### ✨ 新的
- **🔥 P0 · 安全 / 兼容底盘(2 项)**
  1. **🔌 LlmAdapter Provider 适配器层** — 统一 OpenAI/Anthropic/DeepSeek/火山/豆包/OLLAMA 协议,`chat()/stream()/embed()/healthCheck()` 四接口,配合 Fallback LLM Client 切源零改动,支持 Prefix Caching 标记透传
  2. **🛡️ E2B 代码执行沙箱** — 4 后端(e2b 云 / firecracker / local-tmpfs / local-child-process),危险 env 过滤(NODE_OPTIONS/LD_PRELOAD 等),超时 SIGKILL,workspace realpath 挂载防 symlink 穿越,PTC Code Mode 产出代码统一在此执行

- **💎 P1 · 代码能力 + 测试体验 + 插件 DX(7 项)**
  3. **📁 FS Driver Read/Write 双权限分离** — ReadDriver 和 WriteDriver 独立接口,插件只拿 read 通道,resolveAllowed 做 realpath 解析防 symlink 穿越,WriteDriver 写前自动 backup 到 .backup/ 目录
  4. **🔍 LSP 语言服务接入** — 支持 tsserver/pyright/rust-analyzer/gopls/jdtls,definition 跳转 / references 引用查找 / hover 悬停签名 / completion 补全 / diagnostics 诊断 / documentSymbols 文档符号 / rename 跨文件重命名,JSON-RPC stdio 通信
  5. **📊 Domain Usage 计费账本 + Event 事件源** — 每次 LLM 调用记录 prompt/completion/cached token + costUsd 估算,按 provider/model/day 汇总;EventBus 16 种事件类型,Hook/Inflight/Goal/Jobs 产生事件流
  6. **🔌 Ports 端口化(IClock/IRandom/IEnv)** — SystemClock/CryptoRandom/ProcessEnv 生产实现 + FakeClock(advance 前拨)/FakeRandom(sequence)/FakeEnv 测试实现,Scheduler nextFire 测试跑 100 倍速
  7. **🌐 Browser Use 浏览器自动化** — 10 个动作(navigate / click / type / scroll / screenshot / extract / wait / evaluate / back / forward / close),URL pattern 黑名单 + maxTabs 限制 + evaluate script 安全审查(eval / Function / require 禁止),Playwright 延迟加载
  8. **🌿 Git Worktree 多任务隔离** — 每个并行 Job 自动 `git worktree add` 独立分支沙箱,分支名自动生成防冲突,merge 冲突返回 conflictFiles 不强推,prune 清理超过 maxAge 的残留 worktree,并发度从 2 提升到 6-8
  9. **🔌 SDK 门面层(插件开发体验)** — `registerPlugin / registerTool / on(Hook.Phase) / registerCapability` 门面 API,插件 30 行可 Hello World,自动注入 log / config / emit / fs / llm 上下文,dispose 时自动清理 Hook + Tool + Capability

### ⚠️ 说明
- 以上 9 项能力**全部为本地自研核心代码实现**,不直接复制 DeepSeek Harness / kun-reference 源码,遵循 MIT 协议精神与「源码不公开」内部约定
- 核心代码路径:`src/main/core/`(累计 30 个 TypeScript 文件 + 1 个 types.ts),仅本地维护,**不推送到 GitHub 公开仓**
- types.ts 扩展至 43 大模块(G1-G9 新增类型约 500 行),跨模块入参出参强类型约束
- HookEngine 新增 `unregisterByPrefix()` 方法,配合 SDK Facade 插件卸载时批量清理

## ✦ HELIOS V3.11 · 二阶段 22 项深化 · P0+P1+DSH 特有高阶能力 一次性落地

### ✨ 新的
- **🔥 第一层 · 循环与修复（P0 5 项 + PTC 代码模式）**
  1. **🧰 ToolCall JSON 修复引擎** — 三层自动修复（wrapper 拆层 / fence 挖 JSON / 超长截断），工具调用失败率目测下降 60-80%
  2. **🔏 Immutable Prefix 前缀指纹** — System/Tools/Pinned/FewShots 合成 SHA256，配合厂商 Prefix Caching 省 30-70% 前缀 Token
  3. **🧩 Compaction Marker 压缩标记** — 压缩产物注入 `<kun:tool_digest sha256>` XML 标记 + 保留 sourceDigest + sourceItemIds，用户可溯源不做黑箱

  5. **🚦 Steering Queue 插嘴转向队列** — 推理中途用户新消息进缓冲队列，安全边界（模型返回完 / 工具结束）自动 drain 注入，纠正不用等整轮结束
  6. **🧑‍💻 PTC 程序化工具调用（DeepSeek Harness 首创 Code Mode）** — 多轮 read→grep→批量 edit 合成一段 TS/Python，受控沙箱一次跑完，模型轮次砍 50-80%

- **💎 第二层 · 可靠性 + 生命周期（P1 7 项）**

  13. **🪵 ExtensionLogWriter 每个插件独立日志** — 大小滚动(默认 2MB×5 份)+ N 天保留，等级 DEBUG/INFO/WARN/ERROR，插件 bug 直接附日志

## ✦ HELIOS V3.9 · 彻底自研核心 · 脱离 Codex

> **日期**：2026-08-14
> **主打**：自研 Agent Loop × 事件溯源会话 × 6 协议直连 LLM × 零外部子进程依赖

### ✨ 新的

- **🔥 彻底脱离 Codex**：移除 `codex/` 子进程、config.toml 写入、jsonl RPC 管道，不再依赖任何外部 Codex App Server 或 CLI
- **自研 HELIOS Core**（`src/main/core/`）——12 大模块完全自研
  - **Agent Loop**：Turn / Step 双层循环，支持多工具调用、流式输出、中断恢复
  - **LLM Client**：直连 5 种协议（`responses` / `chat` / `messages` / `gemini` / `dashscope`）+ 流式 + 工具调用
  - **Tool Registry + Executor**：统一工具注册、执行管道、超时控制、并发守卫、单调检查
  - **Session Event Log**：Event Sourcing 事件溯源，append-only 日志 + 消息派生
  - **Token Economy**：请求级确定性压缩（系统提示 / 工具描述 / 工具结果），省 Token 不丢关键信息
  - **Context Compactor**：双阈值（软/硬/强制）+ 预算驱动跨 Turn 历史折叠
  - **Immutable Prefix**：不可变前缀指纹哈希，启用 LLM Prompt Caching 省算力
  - **Hook Engine**：6 阶段拦截器（PreToolUse / PostToolUse / UserPromptSubmit / TurnStart / TurnEnd / PreCompact）
  - **Tool Storm Breaker**：多维工具风暴检测（重复/无效/循环调用）+ 熔断保护
  - **XCRuntimeClient**：以自研核心实现 CodexRuntimeClient 接口，StarHubRuntime 无感切换
  - **10 个内置工具**：read_file / list_directory / write_file / grep_files / shell_exec / run_project_command / search_files / git_status / git_diff / inspect_workspace
- **架构升级**：参考 DeepSeek Harness「一切皆插件」+ kun-reference「端口/适配器 + 缓存优先循环」优秀设计，小星核心具备同等扩展能力
- **384/384 测试全过 + 构建成功 + tsc --noEmit 零错误**

### 💪 增强

- `StarHubRuntime.createClient` 改为直接传入 `ProviderConfig`，不再走环境变量 + 磁盘配置文件中间环节
- Provider 校验与连接流程更稳定，失败错误消息改为「XC 自研核心」不再提及 Codex
- 线程 source 字段从硬编码 `"codexAppServer"` 更正为标准 `"appServer"`
- 移除 config.toml 写入后，首次连接速度提升（少了磁盘事务 I/O）

### 🐛 修复

- 彻底消除「Codex 进程异常退出导致整个会话断连」问题：核心全在进程内，无外部子进程依赖
- 修复长对话 Token 溢出问题：Context Compactor 双阈值 + 预算驱动自动压缩
- 修复工具调用死循环问题：Tool Storm Breaker 多维检测 + 熔断保护
- 修复 Provider 切换时残留旧环境变量问题：不再走 env 传递，ProviderConfig 内存传递纯净无残留

### 🎨 设计与架构

- 核心层严格遵循「端口/适配器」模式，所有外部依赖通过抽象接口（`ModelClient` / `ToolRegistryPort` / `SessionEventLogPort`）解耦
- Branded ID 系统（`ThreadId` / `TurnId` / `StepId` / `CallId`）防止类型混淆，参考 TypeScript 类型驱动开发最佳实践
- 所有自研模块单元类型覆盖 100%，后续可独立替换任意实现（例如接入本地 OLLAMA 只需新增 LLM Client 适配器）
