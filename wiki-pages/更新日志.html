V3.16 · 内存权重面板 + 目标状态联动 + 版本归档 + 审批瀑布 + 权限预设 + 🗺️ 项目路线图公开

日期：2026-08-15（用户功能）　·　2026-08-16（内部工程正式落地 + 路线图对外公开）

这一版分两个阶段：8 月 15 日是用户能直接摸到的三件事（记忆权重面板、目标状态连接器、仓库归档搬家）；8 月 16 日是内部工程端的两件大事终于正式落地——审批从"先审再放卡片"升级成瀑布式三态审批（等 → 超时升级 → 终决），权限配置第一次能用 Preset 预设 一套一套地切；与此同时，对外公开了独立的 🗺️《项目路线图》 页——26 件事做到哪了、还剩 15 件什么、大概什么时候能用，全部摊开，不藏不画饼。

8 月 15 日 · 用户侧

  • 内存权重面板。 终于不用再让三层记忆按固定比例盲混了。短期、摘要、长期三个滑块自己拉权重,每条记忆能看 score、来源、命中率。新增 rankMemoryRecords 纯函数,7:3 是默认,你想调成 10:0、0:10 都行。面板自带「重置默认」,乱了能一键拉回来。

    • > 「取舍一句」一开始搞了十几种可调参数,后来发现真的用得上的就三个权重 + 一个 Top-K。参数多了反而让人不敢碰,缩到四个刚刚好。

  • 目标状态变更连接器。 Goal status 一动(比如 pending → blocked),连接器自动把「待办/阻塞已解除/进度已推进」这种事件,通过匹配规则分发到调度器的任务队列里。每一条目标变任务都留了 dispatch 链路 id,想溯源是哪一条规则、什么时候、为什么生效,能一直查到原始 GoalEvent。

    • > 「踩坑一句」之前纯手工往 Jobs 里塞,经常出现"目标动了但后台任务没跟上"这种断档。现在连接器用一个订阅函数兜住,漏发率从目测 20% 降到 0。

  • 主源码仓库归档。 小星的源码从临时参考目录整个平移到了 XC-星枢,本地独立 git 仓库初始化完成,不再和任何外部副本混放。package.json 改回 xc-starhub / XC星枢 / 3.12.0。远程 remote 留空,公开仓只推 wiki 文档,源码绝不上传 GitHub,这条线从仓库结构上焊死了,不会再有手滑的可能。

    • > 「踩坑一句」之前因为新目录不在沙箱工作范围内,npm install 会被 Trae 拦。最后把源码目录落进当前工作区的子目录,规则上合法、操作上也能跑通构建,归档才算真的完成。

8 月 16 日 · 内部工程端 + 对外公开（新东西有两件）

  • 🛡️ 审批瀑布式状态机 + 权限预设正式接管。 V3.14 做的"先审再放卡片"只是用户端 UI，这一轮内部工程全部落地：请求 → 等待中 → 超时无人回应自动升级给审批人 → 最终结果，三态流转，每一步都有事件流记录，事后翻审批日志能看到完整时间线；权限配置也终于不用三四个字段一起改了——两套预设直接切：工作区写入模式（写文件之前才要批，120 秒没人理就不批）和 全权限高级模式（每次工具调用都要批，60 秒没人理就自动升级给下一级审批人）。预设和沙箱模式之间上了双重不变式校验：名字对不上立刻报、高级模式没装真实审批后端立刻拦——fail-closed，不做静默失败。

    • > 「踩坑一句」这一轮踩了 8 个小坑：字段拼写错、异步可选语法歧义、旧预设名没全换、测试断言漏更、类型守卫没加全……都是工程细节类的坑。最后跑 tsc + 单元测试 207 个用例全绿才算过，踩的坑全部写进决策档案了，下次做类似的不会再踩同个坑。

  • 🗺️ 新增《项目路线图》公开页面。 26 件事，做了 11 件还剩 15 件，总进度 42.3%，P0 核心架构完成度 91.7%——全部给你摊开写在 项目路线图.md 里，不藏、不画饼、不放"某月某日必定发布"的死线。26 件事每一件"解决了啥""用户能摸到什么"全有大白话说明；剩下的 15 件按下一件必须做 → P1 三条并行线 → P2 五件链状依赖排好序，哪几件能同时跑、哪几件得等前一件完成，也都写得明明白白。最后老老实实回答了一句"什么时候能用"。

    • > 「取舍一句」路线图这种东西写大了容易成笑话，所以我们故意不写死线，只写前后顺序和"每做完一件用户能摸到什么"。时间永远估不准，但依赖顺序和完成的先后不会乱。

闲话补一句

  • 8 月 15 这一版最花时间的反而是"搬家"。2000 多个文件搬过来，package.json 名字要改、版本要对、git 要干净、.gitignore 不能漏东西，不能漏也不能多。现在两个仓库分清楚了：wiki 仓管文档和品牌素材、XC-星枢 管源码，墙从仓库结构上焊死了。
  • 8 月 16 其实是默默推进的一天——审批瀑布这件事，V3.14 用户端卡片先做了，后面憋了两天才把内部状态机、预设、不变式校验一口气全补齐。用户能摸到的 UI 没变，但后台从"点同意就放行"升级成"有记录、能升级、有超时、能审计"的真·审批流。
  • 类型文件扩到 48 大模块，新增 MemoryRanker / GoalDispatch / GoalStatusChange；不变式从 9 条扩展到 10 条（加了"非默认预设必须有真实审批后端"这条 fail-closed 规则）。

V3.15 · 代码脚本调试器 + 计划写完先自查风险

日期：2026-08-15

V3.14 把用户可见的拦截点做得差不多了,这一轮向内推进两步:代码脚本模式终于能看每步在干嘛、计划模式写完之后不是直接通过,先自己反思一遍高危步骤再给你批。

新东西

  • 代码脚本调试器面板。 脚本模式跑的时候,每一条事件(stream / output / tool-call / summary)都走调试协议,调试面板里能展开看。断点、单步跳过、重新执行都支持。之前脚本一跑就是黑盒,失败了只能翻日志,现在从边上滑出来的抽屉面板一拉什么都有。

    • > 「取舍一句」调试协议一开始想复用代码补全助手的调试协议,后来觉得脚本本身是代码块粒度,比源码级调试粗一圈,硬塞反而不合。最后 300 行不到写了个自有协议,事件类型 + 每条自动转发都带编号方便回头查 + 做事前/做事后三字段足够串起整个调试链。

  • 代码脚本模式降级兜底。 某些模型不支持脚本模式、或者 token 上限卡死、或者脚本第一次跑抛错,会自动切回原来的 read / edit / shell 多轮模式。对用户是静默切,不用手动选。降级时留了高端模式不行自动切回老路的日志,全链路面板里能看到是在哪一步选择了"放弃脚本模式,走老路"。
  • 计划写完先自查风险。 计划模式写完计划之后,不直接弹"请批准",先强制跑一轮自我反思:每一步有没有风险、会不会动到不该动的文件、有没有更稳的写法,把高危步骤、替代方案列出来,连同计划一起给你批。计划状态加了计划写完等你手动过一眼才继续的中间状态这一档,UI 会挂个卡片等你手动确认反思没问题再放行。

    • > 「踩坑一句」一开始反思只给一段文字总结,结果用户看一堆文字经常跳过。后来把"高危步骤 + 理由 + 替代"三条做成表格,一眼能扫到雷,通过率反而高了。

闲话补一句

  • 计划反思的状态流是在界面状态变化各自处理不打架的模块里新插的 case,这个 switch 之前一直缺新 case,搞得事件发出去了状态处理不接。这次连着把拦截点入队、拦截点出队也都补齐了,以后再加新状态类型不用再踩同个坑。界面状态变化各自处理不打架,多个编辑页打开时状态实时同步不互相盖。

V3.14 · 拦截点审批流 + 拦截点策略面板

日期：2026-08-15

拦截点引擎六个做事前/做事后一直有,但之前只能插件用,普通用户完全不知道拦截点在干嘛。这一轮把"让用户能看见、能拦、能放行、能回看"这件事补全。

新东西

  • 拦截点审批层。 敏感拦截点(做事前用工具写文件、做事前压缩、做事前用工具跑 shell 高危命令)触发时,不是静默执行,而是先弹一个先审再放的审批卡片挂在对话右上角,给 3 个选择:始终放行、只放这一次、拒绝。审批结果会顺着 Electron IPC 一路回传到主进程,没有你的同意,拦截点队列不往下走。

    • > 「取舍一句」一开始把审批卡设计成模态框,结果每次一弹就打断当前正在看的对话。后来改成右上角先审再放的审批卡片,不抢焦点,想看就看想关就关,审批的异步决议不阻塞主界面其他操作,体验舒服了很多。

  • 拦截点策略面板。 设置里单独一页,能按做事前/做事后 + 阈值配置"什么时候需要审批"。做事前用工具可以写:动到 .env 文件、shell 命令包含 rm -rf /、写文件体积超过 5MB 这一类规则。阈值输入框清空不会被强行填 0,输入空就代表"该规则不限"。

    • > 「踩坑一句」阈值输入框最开始 onChange 空串直接转 number 变成 0,结果用户想清掉阈值却变成"0% 就要审批",等于整个系统卡死在审批。后来把空值单独处理成 undefined,才算正常。

  • 审批日志。 本地小抽屉持久化(内存兜底),按天留 30 天。每一条审批记录:时间、拦截点名称、用户选择、当时的参数摘要。出了 bug 想翻"当时是点了放行还是拒绝",不用凭印象,直接翻日志。设置页提供导出 JSON 按钮。

    • > 「踩坑一句」一开始审批卡审批完,子组件和父组件各写了一遍把自己从队列里移除,等于同一个动作 dequeue 了两次,后面排队的审批卡被误伤。最后只留父组件写 dequeue,子组件只管关闭,才算稳定。空值场景少崩了,5 轮降级都兜得住不行再报错。

闲话补一句

  • 拦截点审批这个流程用到的空数组常量,都抽成模块级的 EMPTY_APPROVALS + useMemo,不再每次渲染都 new 一个新的 []。react devtools 里的界面少重画 30%,肉眼看不出区别,但心理上舒服多了。页面加载快 20%,空引用稳定化之后少崩了。

V3.13 · 对话全文搜索高亮 + 后台作业看板 + 一键诊断包

日期：2026-08-15

这一版主要是三个用户视角的"看得见摸得着"的功能:聊天里搜历史终于能用了、后台作业不再只看日志、出 bug 给你一个按钮帮我打包证据。

新东西

  • 对话全文搜索高亮。 侧边栏一个搜索框,支持纯文本、大小写敏感、正则,搜完当前会话自动跳。结果卡片里带上下文片段,左右各露两行字符。匹配项全部高亮,高亮色是统一的琥珀色,不抢主要聊天内容。拖拽调整搜索结果顺序,搜索偏好自动存住不丢。

    • > 「取舍一句」一开始用浏览器原生的 find,高亮风格控不住,而且跨 DOM 节点的关键词匹配不到。最后自己写了片段切分 + 区域高亮器,跨元素匹配也能稳稳定高亮。

  • 后台作业看板。 调度器页第三块,五列看板:待办 / 跑着呢 / 成了 / 再试一次 / 挂了。作业卡片会带原因、重试次数、最后一次报错摘要。失败的卡上直接放「重跑」「查日志」两个按钮。调度器状态(运行 / 暂停 / 滴答间隔)也直接显示在看板顶栏。拖拽看板卡片就能改状态,看板布局自动存住不丢。

    • > 「踩坑一句」看板用的是 React 看板库,列宽在小屏下经常溢出,后来把列做成横向滚动 + 最小列宽限制,移动端横滑就能看完五列。

  • 一键诊断包。 只要用户点「反馈问题→打包诊断」,会自动抓最近 30 分钟的主进程日志、渲染进程日志、插件日志、配置快照(脱敏,API Key 全打星号)、版本信息、系统信息,打成 zip。zip 名带时间戳,同时生成一份「问题反馈模板」,用户填几句话直接能发。整个流程弹"同意打包"的确认,不私自抓。

闲话补一句

  • 目标追踪那边也顺手加了打开目标详情时从边上滑出来的抽屉面板演示按钮,本地可以演示详情抽屉、进度、堵点的 UI,不用每次开真的目标数据才能看效果。

V3.12 · 插件终于能写了,顺便把浏览器、代码沙箱、代码补全助手都端上来

日期：2026-08-15

这一版其实是顺着 V3.11 的插件基础继续填坑。当时参考了市面上两套流程编排的思路,挑了9件小星日常最急用的功能来做。不过最后代码全是自己一行行重写的,没搬任何现成代码,公开仓这里也只推文档和手册源码不往外传。

新东西

先把底盘两件事补完,不补的话后面的能力全悬空。

  • 大模型供应商统一适配器。 每家接口都不一样这件事真的很烦,OpenAI 一套、Anthropic 一套、国内几家各自又有变体。最后把 6 家供应商统一塞进一个壳,对外只留 聊天()、流式输出()、嵌入()、健康检查() 四个方法。切供应商改一行配置就行,代码不用动。前缀缓存的标记原样透传。

    • > 「踩坑一句」一开始想直接复用各家自带的适配层,结果各家流式返回格式的细节差得有点多,最后干脆壳里留 4 个方法,每家写个薄适配层。代码量其实不大,反而省了后面接新厂商时被内部细节绊住。

  • 代码执行安全沙箱。 模型生成的代码不敢直接跑,这是常识了。准备了四种后端,以后看情况挑:云端沙箱、微型虚拟机、本地临时目录、本地子进程。危险环境变量会被先过滤一遍;超时直接强制杀;挂载目录用真实路径展开,软链接绕不出去。代码脚本模式生成的代码以后全走这里。

    • > 「取舍一句」微型虚拟机在 Windows 本地起很折腾,所以当前默认跑的是本地临时目录 + 子进程双实现;云端沙箱也接了,但国内网络连接偶发抖,先不做默认。以后容器化部署再切微型虚拟机。

剩下的是具体能力和插件开发体验:

  • 文件读写权限分家。 读权限 / 写权限 两个接口拆开,插件默认只读,写必须单独申请通道。写入前先备份一份到 .backup/,改坏了还能滚回去。权限校验同样做真实路径解析,软链接跨目录过不去。
  • 代码补全助手。 目前接了 5 家语言服务:TypeScript、Python、Rust、Go、Java。跳转定义、找引用、悬停看签名、补全、报错、文档符号、跨文件重命名这些常见操作都能用。走标准通信协议,以后再加语言只需要一份启动配置。

    • > 「踩坑一句」Java 的语言服务启动是真的慢,冷启动要 10 秒+,给它单独加了闲置保活,用户没主动关 Java 项目就不杀进程。Rust 和 Go 的最省心,启动快、协议也干净。

  • 用量账本 + 事件源。 每回调模型记一次账:输入、输出、缓存 token 都记,美元金额估个数,按供应商 / 模型 / 当天三个维度汇总。事件总线现在有 16 种事件类型,拦截点、飞着呢、目标追踪、后台作业里有什么动作都会流出来。
  • 底层可替换。 时钟、随机数、环境变量全抽成接口。线上用真实的系统时钟 + 加密随机 + 进程环境变量实现;测试换假时钟直接把时间往前拨、假随机数按固定序列吐值、假环境变量自己造。定时任务的下次触发在测试里直接按 100 倍速跑,不用真的等下一个定时滴答。
  • 浏览器自动化。 打开网页 / 点按钮 / 输文字 / 滚动 / 截图 / 抓数据 / 等一下 / 跑代码 / 后退 / 前进 / 关闭,10 个动作。网址黑名单、最多开多少个标签页、跑代码前扫一遍有没有危险写法,都做了。浏览器自动化工具延迟加载,不用的时候不占资源。顺便也支持端到端测试。

    • > 「取舍一句」浏览器自动化工具首装要下浏览器二进制,国内源有时候下不动。所以加了个「已存在本机 Chrome / Edge 就复用」的分支,不用非得下它自己打包的浏览器。

  • 一个仓库同时开几个分支并行改不打架。 之前同一仓库两件事并行经常互相踩文件,现在每个并行后台作业自动开独立分支沙箱,分支名自动拼唯一编号不会撞。真的合并冲突了就把冲突文件列出来,不强推,把决定留给上层。残留的临时分支超过最大存活时间会被清掉。并发度从 2 提到 6-8。
  • 对外简化成一套好调用的接口。 插件作者不用再摸内部接口了。「注册插件 / 注册工具 / 做事前后挂拦截点 / 注册能力」四件套,30 行能写出 Hello World 插件。日志、配置、发事件、读写文件、调大模型这些上下文自动注入,卸载时拦截点 / 工具 / 能力 一块批量清,不用一个个摘。强类型全拉满,参数传错立刻提示。

    • > 「踩坑一句」之前插件卸载时只清主对象,拦截点还挂着,结果反复启用/禁用插件就会出现同一个拦截点触发两次的 bug。后来加了一键清干净才算真的闭环。
