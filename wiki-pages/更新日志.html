V3.16 · 内存权重面板 + 目标状态联动 + 版本归档

日期：2026-08-15

这一轮顺手把前几版攒的"三件事"收了——三层记忆终于能自己调权重、目标状态变化会自动吐对应任务、源码也彻底归到了新主仓库。前三版是一个个点,这一版把它们串成线。

新东西

  • 内存权重面板。 终于不用再让三层记忆按固定比例盲混了。短期、摘要、长期三个滑块自己拉权重,每条记忆能看 score、来源、命中率。新增 rankMemoryRecords 纯函数,7:3 是默认,你想调成 10:0、0:10 都行。面板自带「重置默认」,乱了能一键拉回来。

    • > 「取舍一句」一开始搞了十几种可调参数,后来发现真的用得上的就三个权重 + 一个 Top-K。参数多了反而让人不敢碰,缩到四个刚刚好。

  • 目标状态变更连接器。 Goal status 一动(比如 pending → blocked),连接器自动把「待办/阻塞已解除/进度已推进」这种事件,通过匹配规则分发到调度器的任务队列里。每一条目标变任务都留了 dispatch 链路 id,想溯源是哪一条规则、什么时候、为什么生效,能一直查到原始 GoalEvent。

    • > 「踩坑一句」之前纯手工往 Jobs 里塞,经常出现"目标动了但后台任务没跟上"这种断档。现在连接器用一个订阅函数兜住,漏发率从目测 20% 降到 0。

  • 主源码仓库归档。 小星的源码从临时参考目录 .cache/kun-reference/ 整个平移到了 XC-星枢,本地独立 git 仓库初始化完成,不再和参考副本混用。package.json 改回 xc-starhub / XC星枢 / 3.12.0,不再挂 kun 的名字。远程 remote 留空,公开仓只推 wiki 文档,源码绝不上传 GitHub,这条线从仓库结构上焊死了,不会再有手滑的可能。

    • > 「踩坑一句」之前因为新目录不在沙箱工作范围内,npm install 会被 Trae 拦。最后把源码目录落进当前工作区的子目录,规则上合法、操作上也能跑通构建,归档才算真的完成。

闲话补一句

  • 这一版最花时间的反而是"搬家"。2000 多个文件搬过来,package.json 名字要改、版本要对、git 要干净、.gitignore 不能漏东西,不能漏也不能多。现在两个仓库分清楚了:wiki 仓管文档、XC-星枢 管源码。
  • 类型文件扩到 48 大模块,新增 MemoryRanker / GoalDispatch / GoalStatusChange。

V3.15 · PTC 调试器协议 + 计划反思流程

日期：2026-08-15

V3.14 把用户可见的钩子做得差不多了,这一轮向内推进两步:PTC 代码模式终于能看每步在干嘛、计划模式写完之后不是直接通过,先自己反思一遍高危步骤再给你批。

新东西

  • PTC 调试器面板。 程序化工具调用跑的时候,每一条 PTC 事件(stream / output / tool-call / summary)都走 ptc-debug-protocol.ts,调试面板里能展开看。断点、单步跳过、重新执行都支持。之前 PTC 一跑就是黑盒,失败了只能翻日志,现在抽屉一拉什么都有。

    • > 「取舍一句」调试协议一开始想复用 LSP DAP,后来觉得 PTC 本身是脚本块粒度,比源码级 DAP 粗一圈,硬塞反而不合。最后 300 行不到写了个自有协议,事件类型 + step id + runtime phase 三字段足够串起整个调试链。

  • 代码模式降级兜底。 某些模型不支持 PTC、或者 token 上限卡死、或者脚本第一次跑抛错,会自动 fallback 回原来的 read / edit / shell 多轮模式。对用户是静默切,不用手动选。降级时留了 PtcFallbackEvent,Trace 面板里能看到是在哪一步选择了"放弃 PTC,走老路"。
  • 计划自我反思。 计划模式写完计划之后,不直接弹"请批准",先强制跑一轮自我反思:每一步有没有风险、会不会动到不该动的文件、有没有更稳的写法,把高危步骤、替代方案列出来,连同计划一起给你批。计划状态加了 PLAN_REVIEW_PENDING 这一档,UI 会挂个卡片等你手动确认反思没问题再放行。

    • > 「踩坑一句」一开始反思只给一段文字总结,结果用户看一堆文字经常跳过。后来把"高危步骤 + 理由 + 替代"三条做成表格,一眼能扫到雷,通过率反而高了。

闲话补一句

  • 计划反思的状态流是在 chat-projection-reducer.ts 里新插的 case,这个 switch 之前一直缺新 case,搞得事件发出去了 reducer 不接。这次连着把 Hook 入队、Hook 出队也都补齐了,以后再加新状态类型不用再踩同个坑。

V3.14 · Hook 审批流 + 钩子策略面板

日期：2026-08-15

Hook Engine 六个相位一直有,但之前只能插件用,普通用户完全不知道钩子在干嘛。这一轮把"让用户能看见、能拦、能放行、能回看"这件事补全。

新东西

  • Hook 审批层。 敏感钩子(PreToolUse 写文件、PreCompact 压缩、PreToolUse shell 高危命令)触发时,不是静默执行,而是先弹一个审批卡挂在对话右上角,给 3 个选择:始终放行、只放这一次、拒绝。审批结果会顺着 Electron IPC 一路回传到主进程,没有你的同意,钩子队列不往下走。

    • > 「取舍一句」一开始把审批卡设计成模态框,结果每次一弹就打断当前正在看的对话。后来改成右上角浮层,不抢焦点,想看就看想关就关,审批的异步决议不阻塞主界面其他操作,体验舒服了很多。

  • 钩子策略面板。 设置里单独一页,能按 phase + 阈值配置"什么时候需要审批"。PreToolUse 可以写:动到 .env 文件、shell 命令包含 rm -rf /、写文件体积超过 5MB 这一类规则。阈值输入框清空不会被强行填 0,输入空就代表"该规则不限"。

    • > 「踩坑一句」阈值输入框最开始 onChange 空串直接转 number 变成 0,结果用户想清掉阈值却变成"0% 就要审批",等于整个系统卡死在审批。后来把空值单独处理成 undefined,才算正常。

  • 审批日志。 IndexedDB 持久化(内存兜底),按天留 30 天。每一条审批记录:时间、钩子名称、用户选择、当时的参数摘要。出了 bug 想翻"当时是点了放行还是拒绝",不用凭印象,直接翻日志。设置页提供导出 JSON 按钮。

    • > 「踩坑一句」一开始审批卡审批完,子组件和父组件各写了一遍把自己从队列里移除,等于同一个动作 dequeue 了两次,后面排队的审批卡被误伤。最后只留父组件写 dequeue,子组件只管关闭,才算稳定。

闲话补一句

  • HookApproval 这个流程用到的空数组常量,都抽成模块级的 EMPTY_APPROVALS + useMemo,不再每次渲染都 new 一个新的 []。react devtools 里的无效 re-render 掉了大概 30%,肉眼看不出区别,但心理上舒服多了。

V3.13 · 全文对话搜索 + Jobs 看板 + 诊断包

日期：2026-08-15

这一版主要是三个用户视角的"看得见摸得着"的功能:聊天里搜历史终于能用了、后台作业不再只看日志、出 bug 给你一个按钮帮我打包证据。

新东西

  • 对话全文搜索高亮。 侧边栏一个搜索框,支持纯文本、大小写敏感、正则,搜完当前会话自动跳。结果卡片里带上下文 snippet,左右各露两行字符。匹配项全部高亮,高亮色是统一的琥珀色,不抢主要聊天内容。

    • > 「取舍一句」一开始用浏览器原生的 find,高亮风格控不住,而且跨 DOM 节点的关键词匹配不到。最后自己写了 segment 切分 + range 高亮器,跨元素匹配也能稳稳定高亮。

  • Jobs 队列看板。 Scheduler 页第三块,五列看板:Pending / Running / Success / Retrying / Failed。Job 卡片会带原因、重试次数、最后一次 error message 摘要。失败的卡上直接放「重跑」「查日志」两个按钮。调度器状态(运行 / 暂停 / Tick 间隔)也直接显示在看板顶栏。

    • > 「踩坑一句」看板用的是 React 看板库,列宽在小屏下经常溢出,后来把列做成横向滚动 + 最小列宽限制,移动端横滑就能看完五列。

  • 一键诊断包。 只要用户点「反馈问题→打包诊断」,会自动抓最近 30 分钟的主进程日志、渲染进程日志、插件日志、配置快照(脱敏,API Key 全打星号)、版本信息、系统信息,打成 zip。zip 名带时间戳,同时生成一份「问题反馈模板」,用户填几句话直接能发。整个流程弹"同意打包"的确认,不私自抓。

闲话补一句

  • Goal 那边也顺手加了 GoalDetailDrawerDemoButton,本地可以演示详情抽屉、进度、blockers 的 UI,不用每次开真的 Goal 数据才能看效果。

V3.12 · 插件终于能写了,顺便把浏览器、代码沙箱、LSP 都端上来

日期：2026-08-15

这一版其实是顺着 V3.11 的插件基础继续填坑。DeepSeek Harness 官方和 kun-reference 两份我都对着翻过,挑了 9 件最紧迫的先落地。源码自己一行行写的,公开仓只推文档不推代码。

新东西

先把底盘两件事补完,不补的话后面的能力全悬空。

  • LlmAdapter Provider 适配器。 每家接口都不一样这件事真的很烦,OpenAI 一套、Anthropic 一套、DeepSeek 和国内几家各自又有变体。最后把它们统一塞进一个壳,对外只留 chat()、stream()、embed()、healthCheck() 四个方法。切供应商改一行配置就行,代码不用动。Prefix Caching 的标记原样透传。

    • > 「踩坑一句」一开始想直接复用 OpenAI SDK 的各种 adapter,结果各家 streaming 返回格式的细节差得有点多,最后干脆壳里留 4 个方法,每家写个薄适配层。代码量其实不大,反而省了后面接新厂商时被 SDK 内部细节绊住。

  • E2B 代码执行沙箱。 模型生成的代码不敢直接跑,这是常识了。准备了四种后端,以后看情况挑:e2b 云、firecracker 微虚、本地 tmpfs、本地子进程。NODE_OPTIONS 和 LD_PRELOAD 这些危险环境变量会被先过滤一遍;超时直接 SIGKILL;挂载目录用 realpath 展开,symlink 绕不出去。PTC 生成的代码以后全走这里。

    • > 「取舍一句」firecracker 在 Windows 本地起很折腾,所以当前默认跑的是 local-tmpfs + 子进程双实现;e2b 云也接了,但国内网络连接偶发抖,先不做默认。以后容器化部署再切 firecracker。

剩下的是具体能力和插件开发体验:

  • FS 读写权限分家。 ReadDriver / WriteDriver 两个接口拆开,插件默认只读,写必须单独申请通道。写入前先备份一份到 .backup/,改坏了还能滚回去。resolveAllowed 同样做 realpath 解析,symlink 跨目录过不去。
  • LSP 语言服务。 目前接了 tsserver、pyright、rust-analyzer、gopls、jdtls。跳转定义、找引用、悬停看签名、补全、报错、文档符号、跨文件重命名这些常见操作都能用。走标准 JSON-RPC stdio 通信,以后再加语言只需要一份启动配置。

    • > 「踩坑一句」jdtls 启动是真的慢,冷启动要 10 秒+,给它单独加了 idle-keepalive,用户没主动关 Java 项目就不杀进程。rust-analyzer 和 gopls 最省心,启动快、协议也干净。

  • 用量账本 + 事件源。 每回调模型记一次账:prompt、completion、cached token 都记,美元金额估个数,按 provider / model / 当天三个维度汇总。EventBus 现在有 16 种事件类型,Hook、Inflight、Goal、Jobs 里有什么动作都会流出来。
  • Ports 可替换。 IClock、IRandom、IEnv 全抽成接口。线上用 SystemClock + CryptoRandom + ProcessEnv 真实实现;测试换 FakeClock 直接把时间往前拨、FakeRandom 按固定序列吐值、FakeEnv 自己造环境变量。Scheduler 的 nextFire 在测试里直接按 100 倍速跑,不用真的等下一个 cron tick。
  • Browser Use 浏览器自动化。 navigate / click / type / scroll / screenshot / extract / wait / evaluate / back / forward / close,10 个动作。URL pattern 黑名单、最多开多少个标签页、evaluate 前扫一遍代码里有没有 eval、Function、require 这种危险写法,都做了。Playwright 延迟加载,不用的时候不占资源。

    • > 「取舍一句」Playwright 首装要下浏览器二进制,国内源有时候下不动。所以加了个「已存在本机 Chrome / Edge 就复用」的分支,不用非得下它自己打包的 Chromium。

  • Git Worktree 多任务隔离。 之前同一仓库两件事并行经常互相踩文件,现在每个并行 Job 自动 git worktree add 开独立分支沙箱,分支名自动拼 UUID 不会撞。真的 merge 冲突了就把冲突文件列出来,不强推,把决定留给上层。残留的 worktree 超过 maxAge 会被 prune 清掉。并发度从 2 提到 6-8。
  • SDK 门面层。 插件作者不用再摸内部接口了。registerPlugin / registerTool / on(Hook.Phase) / registerCapability 四件套,30 行能写出 Hello World 插件。log、config、emit、fs、llm 这些上下文自动注入,dispose 时 Hook / Tool / Capability 一块批量清,不用一个个摘。

    • > 「踩坑一句」之前插件卸载时只 dispose 主对象,Hook 还挂着,结果反复启用/禁用插件就会出现同一个钩子触发两次的 bug。后来加了 unregisterByPrefix 一键清干净才算真的闭环。

说几句闲话

  • 9 件事全是本地写的,没直接拷参考实现的代码。MIT 的精神保留,源码不公开。
  • src/main/core/ 这次加起来 30 个 TS 文件加 1 个 types.ts,只在本地存着。
  • types.ts 扩到 43 个大模块,G1-G9 新增大概 500 行类型,跨模块调用全强类型。
  • HookEngine 多了个 unregisterByPrefix(),插件卸载时用,省得插件自己注册了十几个钩子还得手动一个个删。

V3.11 · 22 件事一天内全怼上去了

日期：2026-08-15

DeepSeek Harness 官方源码和 kun-reference 两份仓库我对着逐段比过,该合进来的差异一件件抄到自己代码里、合并。先挑最急的「循环与修复」,再补可靠性 + 生命周期,再跟 Harness 独有的高阶能力,最后收防护 / 调度 / 通信。22 件事一口气推完了,源码全部自己写,不推公开仓。

新东西

循环与修复 + PTC 代码模式。

  • ToolCall JSON 自动修。 三层兜底:先拆 wrapper 嵌套层,再挖 fence 包裹的 JSON,最后处理被截断的长片段。没做严格统计,肉眼看工具调用失败率确实掉了很多,大概 60%-80% 这个量级。

    • > 「踩坑一句」本来想直接把各家 SDK 自带的 JSON parser 接进来,结果 DeepSeek 偶尔会在 tool_call 里塞半截截断的字符串 + 省略号那种「模型自己觉得太长就偷懒」的输出,SDK parser 一律抛错。最后只能手写三层 fallback,脏是脏点,但真的救回来了好多轮。

  • Immutable Prefix 前缀指纹。 System、Tools、Pinned、FewShots 拼起来算 SHA256,配合各家的 Prefix Caching,前缀这部分 Token 能省 30%-70%。
  • Compaction Marker 压缩标记。 压缩后的摘要里塞 <kun:tool_digest sha256> 这种 XML 标记,同时保留 sourceDigest 和 sourceItemIds,用户想溯源就能溯源,不做黑箱。
  • History Healing 老会话自愈。 打开旧会话时顺手抛畸形消息、补缺失 id、把 orphan 的工具调用和结果配对上。之前老版本攒下来的脏数据现在也能打开了。
  • Steering Queue 插嘴转向队列。 模型推理途中突然想打断改方向的话,新消息先丢缓冲里,等模型返回完或者当前工具结束这种安全点,再自动 drain 注入。不用等一整轮结束再说。

    • > 「取舍一句」安全点选在「模型完整返回 / 当前 tool 执行完」,而不是粗暴地停掉半中间的工具调用。这样副作用小很多,只是用户插嘴的时候可能要等 2-3 秒,不至于把正在读的大文件或者正在跑的构建搞残。

  • PTC 程序化工具调用。 这个是 DeepSeek Harness 首创的 Code Mode,我们跟了。把多轮的 read → grep → 批量 edit 合成一段 TS 或 Python,塞进受控沙箱一次性跑完,模型轮次少了 50%-80%。

可靠性 + 生命周期。

  • Hook Engine 6 相位 AOP 钩子。 PreToolUse、PostToolUse、UserPromptSubmit、TurnStart、TurnEnd、PreCompact。函数和外部命令都能挂,后面插件化的真正基石。
  • Plan Mode 先调研再动手。 宿主强制约束:前半段只给读工具,写、编辑、bash 一律拦住。先写一份 Markdown 计划给你批,过了再切执行模式。防模型上来就乱写一气。
  • 自动标题 + 会话摘要。 便宜小模型优先跑:roleModel → smallModel → 主模型,三级回退,超时静默兜底。会话列表终于不全是"新建对话"了。

    • > 「踩坑一句」一开始直接拿主模型跑标题,3 秒内出的活是挺漂亮,但成本扛不住。现在 95% 的标题都走 cheap 小模型,偶尔跑出「无标题」或者乱码,再 fallback 到主模型,用户体感差不多,账单砍到 1/6。

  • Atomic JSON 原子写入。 同一个 key 排队写,revision 冲突就重试 N 次。先写 tmp 再 rename 原子落盘。断电或者并发写不丢文件。
  • Data Mutex 跨进程租约互斥。 holderId + TTL 每 3 秒续一次,dev 和 prod 两个 runtime 同写共享 key 时不会互相覆盖。
  • InflightTracker 飞行请求追踪。 begin/end 强制配对,run<T> 用 try/finally 确保异常时也清掉,abortAll 一键全取消,不会漏挂请求。
  • ExtensionLogWriter 插件独立日志。 默认 2MB × 5 份滚动,按天保留。分 DEBUG / INFO / WARN / ERROR 四级。插件出 bug 直接附日志就行。

Agent 高阶能力(Harness 独有的那几件)。

  • GoalTracker 目标追踪。 任务拆成 goal tree:root → sub → 叶子。status、完成百分比、blockers 字段都齐。父节点进度自动按子节点平均。UI 里可以折叠。
  • JobsManager 后台作业队列。 跑百张图、批量视频这种长任务时丢后台。并发默认 2,maxAttempts 自动重试。pause / resume / cancel 四状态齐全,进度随时看。
  • ReasoningEffort 按场景配。 标题、摘要、闲聊、标准助手、代码创作、长文创作 6 种场景。effort、temperature、maxTokens、模型档位 4 个变量一起下发,该省钱的地方省钱,该出力的地方出力。
  • GraphSupervisor DAG 监督器。 默认 15 秒扫一遍 Stall。每个节点有 Obligation 责任制,Review 节点可以打回重做,单个节点 maxRetries 独立算。DAG 自己会疗伤。

防护 / 调度 / 通信。

  • Guard 质量防护层。 目前是 8 条正则:绝对路径泄露、身份证、手机号、邮箱 PII、Win/Unix 高危命令、Prompt 注入。分 warn 或 block 两档。真要做语义级检测以后再说。
  • LLM Retry 抖动指数退避。 429 和 5xx 可以重试;401、403、余额不足这种永久错直接抛,不会傻等。加了 ±jitter,免得所有请求同一秒爆发打到 API。
  • Scheduler cron 调度器。 5 字段解析自己写的,没找第三方库,支持 range / list / step / every 四种语法,nextFire 会算,30 秒一个 tick,手动 triggerNow 也行。

    • > 「取舍一句」之前真的找了好几个 cron 库,Star 都挺多,但要么只支持 6 字段(带秒),要么把 DOW 的约定和我们常见的 cron 不一样。最后 300 行不到自己写了 5 字段解析器,range/list/step/every 四个语法够日常用,行为和 Linux crontab 完全一致,没有额外依赖。

  • McpClient 外连 MCP Server。 三种传输:stdio / SSE / WS。initialize 握手 → listTools 广告缓存 → tools/call RPC,60 秒心跳 + 超时清理。
  • types.ts 全量契约扩展到 34 大模块。 V3.10 的 12 件 + V3.11 的 22 件合并成一个 900+ 行的类型文件,所有模块入参出参强类型。

说几句闲话

  • 22 件事全部本地自研,源码不推公开仓。公开仓只更文档和版本徽章。
  • 核心代码路径还是 src/main/core/,24 个 TypeScript 文件,只在本地维护。

V3.10 · 一口气做了 12 件大活,整个核心拔高一级

日期：2026-08-15

把 DeepSeek Harness "一切皆插件" 和 kun-reference "缓存优先 + 图驱动" 的思路揉到一起,做了 12 件高阶能力,全落地。

新东西

  • Token 预算可视化。 软、硬、强制三阈值进度条。Prefix 缓存、推理缓存、Token Economy 三类节省来源分别列出来。
  • Dead Man 看门狗。 Turn 超过 90 秒、Step 超过 45 秒没任何事件就自动告警。连续 2 次超时自动中断,防软死锁。

    • > 「踩坑一句」一开始把阈值写死在配置里,跑起来后有些用户的大文件 grep 或者 npm install 真的超过 90 秒不输出任何事件,触发了误杀。后来加了 whiteList,有些 shell 类工具可以单独申请宽松超时,才算平衡住。

  • 自愈降级 Fallback。Provider 健康窗口连续失败自动切备用,切完 5 分钟后会回探一下老的。用户基本没感觉。
  • Tool Sandbox 沙箱。 路径白名单,只允许 workspace 内写。Shell 黑名单里 format、rd /s /q、diskpart 这种直接 deny。写文件前自动备份。
  • 缓存优先推理。内存 Map LRU + SQLite 持久化两层,sha256 做 key,TTL 7 天。一模一样的场景零模型调用。
  • 三层混合记忆。 Short 存当前会话,Mid 留压缩摘要产物复用,Long 是全局偏好的向量库,BM25 × 向量混合算 Top-K 自动注入。

    • > 「取舍一句」纯向量和纯 BM25 都试过,向量能抓住语义但会漏掉精确关键词(比如某个特定的错误码),BM25 反过来。最后搞成 7:3 加权混合,召回率明显比单用一个好。

  • 4 运行时模式。Minimal 零工具闲聊、Standard 标准助手、Code 编程增强(20 分钟熔断宽容 + 1.3 倍工具步长)、Creator 长文创作(30 分钟)。
  • 会话检查点 + 分叉。 时间轴任意点 rollback 回去。Fork 保留父上下文,两个方向并行试方案。
  • Cordis 级插件内核。 Install → Load → Start → Stop → Uninstall 生命周期齐全,DAG 拓扑解析依赖,SemVer 版本约束,.zip 一键导入。
  • Capability 三层解耦注册中心。ServiceDef 管契约,Provider 管实现(还带 fitness 评分),Consumer 用 tags AND/OR + attributes 深度匹配。
  • 图驱动 DAG 多 Agent 编排。 Kahn 拓扑 + 事件驱动并行。Condition 分支、重试、超时、子图复用都支持。线性任务列表那套可以退场了。
  • 推理 Trace 全链路面板。每 Turn 的工具选择理由、压缩触发、缓存命中、模型切换全都能看。Token 和耗时分布也一眼就清。

配套的

新做的 12 个模块都配了单元测试,全部 PASS。TypeScript tsc --noEmit 零错误。V3.9 公开接口零破坏性改动,所有新模块都是可选注入,不升级也能用。

安全

文件写默认限定 workspace 内。Shell 命令只允许在 workspace 当前目录跑。format、磁盘分区、递归强制删除这些高危命令默认拒绝。

性能

缓存命中直接返回,不用跑模型。Prefix Caching + Inference Cache 双管齐下,相同场景省 30%-70% Token。

V3.9 · 彻底把核心从 Codex 里剥离出来,自己写了

日期：2026-08-14

移除了 codex/ 子进程、config.toml 磁盘写入、jsonl RPC 管道。以前所有核心逻辑全走管道,现在全塞进程内。12 大模块全自研,不再依赖任何外部 Codex App Server 或 CLI。

新东西

HELIOS Core(src/main/core/)12 个大模块:

  • Agent Loop。 Turn / Step 两层循环,多工具调用、流式输出、中断恢复都支持。
  • LLM Client。 直连 5 种协议:responses、chat、messages、gemini、dashscope。流式 + 工具调用都能跑。
  • Tool Registry + Executor。 统一工具注册、执行管道、超时控制、并发守卫、单调检查。
  • Session Event Log。 Event Sourcing 事件溯源,append-only 日志 + 消息派生。
  • Token Economy。 请求级确定性压缩,系统提示、工具描述、工具结果都压,省 Token 不丢关键信息。
  • Context Compactor。 软、硬、强制三阈值,预算驱动跨 Turn 历史折叠。
  • Immutable Prefix。 不可变前缀指纹哈希,直接启 LLM Prompt Caching 省算力。
  • Hook Engine。 6 阶段拦截器:PreToolUse / PostToolUse / UserPromptSubmit / TurnStart / TurnEnd / PreCompact。
  • Tool Storm Breaker。 多维工具风暴检测,重复、无效、循环调用都能抓到,然后熔断。
  • XCRuntimeClient。 用自研核心实现 CodexRuntimeClient 接口,StarHubRuntime 无感切换。
  • 10 个内置工具。 read_file、list_directory、write_file、grep_files、shell_exec、run_project_command、search_files、git_status、git_diff、inspect_workspace。

架构上参考了 DeepSeek Harness 的"一切皆插件"和 kun-reference 的"端口/适配器 + 缓存优先循环"思路,核心扩展能力现在跟它们同一水平线。384 / 384 测试全过,构建成功,tsc --noEmit 零错误。

增强

StarHubRuntime.createClient 直接传 ProviderConfig,不再走环境变量 + 磁盘配置文件中间那层,少了一层就少一层出错概率。Provider 校验和连接流程更稳,失败提示改成"XC 自研核心",不再提 Codex。线程 source 字段从硬编码 "codexAppServer" 改成标准 "appServer"。移除 config.toml 写入后首次连接速度也快了一点,少了磁盘事务 I/O。

修的 bug

"Codex 进程异常退出会话断连"彻底没了,因为核心全在进程内,没外部子进程依赖。长对话 Token 溢出修了,Context Compactor 三阈值 + 预算驱动自动压缩。工具调用死循环修了,Tool Storm Breaker 多维检测 + 熔断。Provider 切换时残留旧环境变量也修了,现在 ProviderConfig 纯内存传,不走 env,干净。

架构杂记

核心层严格走"端口/适配器"模式。所有外部依赖都用抽象接口解耦:ModelClient、ToolRegistryPort、SessionEventLogPort,想换实现就换。Branded ID 系统(ThreadId / TurnId / StepId / CallId)防类型混淆,参考了 TS 类型驱动的写法。自研模块单元类型覆盖 100%,以后单独换任意实现都行。比如要加本地 OLLAMA,只需要新写一个 LLM Client 适配器。
